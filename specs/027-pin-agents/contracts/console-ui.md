# Console UI contract: Pin agents (CLEAN-216)

What a person sees in each console, and what the browser checks assert.

## Ordering rule (both consoles)

```
admin agent(s) → pinned agents → everyone else
```

inside each block the list's own order. Applied by:

| Surface | Function | Inner order |
|---|---|---|
| app side rail and List view (`Rail.vue`) | `railOrder` | arrival (API: newest first) |
| app Drum (`Drum.vue`) | `railOrder` | arrival |
| app Orbit (`Orbit.vue` via `orbitLayout`) | `orbitOrder` | pinned block, then status rank → admin → arrival |
| admin rail (`useAgentRailEntries`) | admin `railOrder` | arrival |

The rule holds while a search term filters the list: the comparator runs on
the filtered set.

## Pin state icon

| Surface | Element | Accessible name |
|---|---|---|
| app rail row | `<Icon name="pin">` after the name, before the admin shield if both | visually hidden `$t('sheet.pinned')` |
| app orbit node | small badge on the node, mirrors the admin shield badge placement | the node's `aria-label` gains `· Pinned` (via `$t('sheet.pinned')`) |
| app drum card | badge next to the admin shield | visually hidden `$t('sheet.pinned')` |
| app sheet | icon beside the name in the fold line | visually hidden `$t('sheet.pinned')` |
| admin rail row | `IconPin` after the name | `title="Pinned"` |
| admin header | `IconPin` after the name, beside `IconShield` | `title="Pinned"` |

Unpinned agents show nothing.

## Toggle control

| Console | Where | Who sees it | Label |
|---|---|---|---|
| app | agent sheet action row, with Restart / Stop / Start, before Share | `canManage` (Owner / Admin) | `$t('sheet.pin')` / `$t('sheet.unpin')`, icon `pin` / `pin-off` |
| admin | agent page header, between Stop / Start and the actions menu, icon-only outline button | everyone on the admin console (Owner / Admin by login) | `title="Pin"` / `title="Unpin"`, `aria-pressed` = pinned |

Behaviour:

1. Click → record patched at once (icon appears / disappears, lists reorder).
2. Request `PUT /agents/:id { pinned }`.
3. Success → the reply upserts the record (no visible change).
4. Failure → rollback; app shows `$t('sheet.pin_failed')` in the sheet's
   failure line (the one Start / Stop use); admin shows the message in the
   header's lifecycle error line.
5. While the request runs the control is disabled (`busy` / `toggling`).


## Browser checks (`specs/027-pin-agents/e2e/`)

`pin.mjs` (app, Owner login from `.env.project`):

- pick the last unpinned non-admin agent in the rail; open it; press Pin;
- assert: sheet shows Unpin; rail row 1 (after the admin agent) is this
  agent; switch to Drum: first card; switch to Orbit: first node after the
  admin agent on the inner ring; the icon exists on each;
- reload: still pinned (server truth);
- press Unpin; assert the order is back and no icon remains;
- screenshots `pin-sheet-1440.png`, `pin-orbit-1440.png`, `pin-rail-390.png`.

`pin.mjs --as user` (a seeded `User` role, or skipped with a note if the seed
has none): opens a pinned agent, asserts the icon and no Pin / Unpin button.

`admin-pin.mjs` (admin on :3001): pin from the header, assert the rail row
order and icon, screenshot `admin-pin-1440.png`; unpin. If the admin login
cannot be scripted, done by hand and said so in the ticket.

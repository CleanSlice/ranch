# Implementation Plan: Embed chat tokens scoped to the chat, transcripts only for their owner

**Branch**: `fix/CLEAN-175-embed-token-scope` | **Date**: 2026-10-26 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/022-embed-token-hardening/spec.md`
| **Ticket**: [CLEAN-175](https://dreamvention.atlassian.net/browse/CLEAN-175)

## Summary

Four API-only changes, in this order: (R0) require a JWT on every route by
default with a test-pinned `@Public()` allowlist, copied from the Mazda fork's
shape; (R1) stamp embed tokens with `typ: 'embed'` and refuse them in the
platform-side verifiers so they open only the chat; (R3) hand a transcript to
its owner or an admin only, uniform 403 otherwise, anonymous and share
channels unchanged; (R5) validate the minted subject and refuse collisions with
reserved channel names and existing user ids. Decisions and rejected
alternatives are in [research.md](research.md); contracts in
[contracts/](contracts/); verification in [quickstart.md](quickstart.md).

## Technical Context

**Language/Version**: TypeScript 5.7 on Node 22, NestJS API (`api/`)

**Primary Dependencies**: `@nestjs/core` (`APP_GUARD`, `Reflector`), `@nestjs/jwt`, `class-validator`, existing guards in `api/src/slices/user/auth/guards`

**Storage**: none changed. Transcripts stay in the runtime's `data/sessions/bridle:<channel>.jsonl`; one read of the `User` table per embed mint

**Testing**: Jest (colocated `*.spec.ts`), run as `npx jest <paths>` after `npx prisma generate`; typecheck via `bun run build`

**Target Platform**: Linux containers (Kubernetes) for upstream prod and the Mazda dev/prod installs; the change reaches the fork via the next catch-up merge

**Project Type**: web service (API) with two Nuxt consoles that need no change

**Performance Goals**: no measurable change; one extra indexed lookup on `POST /auth/embed/token`, one claim check per guarded request

**Constraints**: the allowlist and guard wiring must match the fork (FR-009); console 401 contract (`TOKEN_MISSING` / `TOKEN_EXPIRED` / `TOKEN_INVALID`) unchanged; no token, channel existence or setting value in logs or error bodies (FR-010)

**Scale/Scope**: `api/` only; 43 controllers scanned, ~15 files get `@Public()`, 6 source files change behaviour, 5 spec files touched

## Phase 1: Design

Done: [data-model.md](data-model.md), [contracts/](contracts/),
[quickstart.md](quickstart.md).

Implementation order (for `/speckit-tasks`):

1. **R0 first, as its own commit**: `APP_GUARD` wiring, `@Public()` markers,
   `publicRoutes.spec.ts`. Run the full API spec suite once here: this is the
   step that can break a caller that never held a token, and the test
   pins the surface before anything else moves.
2. **R1**: `typ` claim, `isEmbedToken`, guard and card-guard refusal, specs.
3. **R5**: DTO pattern, user-id collision check, specs. (Before R3 so the
   transcript rule never meets a `sub` it was not designed for.)
4. **R3**: `requireChannelAccess` owner rule, `CHANNEL_FORBIDDEN`, specs.
5. Gates: `npx jest` on the touched paths, `bun run build`; manual quickstart
   on a local API; the handoff's section 8 script once deployed to dev-mazda
   through the fork's catch-up.
6. PR into `main` with the twin-console statement, the commands run, and the
   fork follow-up (a2a + OAuth exemptions) called out for the catch-up merge.
